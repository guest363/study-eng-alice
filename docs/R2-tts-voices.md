# R2 — голоса TTS на устройствах Алисы

Дата: 25.09.2026 · Гейт G2, задача 7 · Источники: спецификация Web Speech API и сводки
по поведению браузеров (MDN, Readium Speech, «Cross browser speech synthesis»).

Задача ресерча: какие `en-US`/`en-GB`-голоса реально есть на планшете/телефоне Алисы
(Chrome Android / Safari iOS) и что делать, если голосов нет. Устройство Алисы пока
не названо (task.md §12, вопрос 8), поэтому ниже — поведение по платформам и
стратегия выбора, которую не придётся переделывать под конкретную модель.

## Главное: список голосов приходит асинхронно

| Платформа | Первый `getVoices()` | Источник |
|---|---|---|
| Chrome desktop, Chrome Android | **пустой массив**, список приходит по `voiceschanged` | MDN, Readium |
| Firefox Android | пустой, список — по `voiceschanged` (после обновления доступен сразу) | Readium |
| Firefox desktop, Safari desktop | обычно готов сразу | Readium |
| Safari iOS/iPadOS | отдаёт не весь установленный набор, отдаёт меньше голосов | Readium |
| Chrome Linux | **синтез выключен**, список всегда пуст | Readium |
| Firefox с `privacy.resistFingerprinting` | список всегда пуст, `speak()` падает с ошибкой | crawlex |

Вывод: голоса нельзя спрашивать один раз при загрузке. Движок подписывается на
`voiceschanged` и обновляет список, пока он пуст (`packages/media/src/tts.ts`).
Если событие не пришло за 2 секунды — работаем с тем, что есть.

## Формат `lang` различается по платформам

- Chrome Android / Samsung: `en_US` (с подчёркиванием);
- Firefox Android: `eng-GBR-f000` (трёхбуквенный код + суффикс);
- остальные: `en-US`, `en-GB` (BCP 47).

Поэтому выбор голоса идёт по нормализованному префиксу: регистр вниз, `_` → `-`,
совпадение по началу строки. Точное совпадение `en-us`/`en-gb` — в приоритете, дальше
любой `en-*`, иначе `null` (озвучка не включается, приложение работает).

## Chrome Android: голоса есть не всегда

Chrome отдаёт нефильтрованный список языков, а не реально установленные голоса: если
языковой пакет не скачан, синтезатор молча переключается на другой английский голос.
Отдельный `default`-флаг не выставляется. Практический вывод: **настройка «голос»
в родительском уголке не может быть гарантией** — движок запоминает выбор, но всегда
проверяет, что выбранный голос появился в списке, иначе берёт лучший доступный.

## Голоса-«шутки» не берём

macOS/iOS поставляют служебные голоса: Albert, Bad News, Bells, Boing, Bubbles,
Cellos, Jester, Organ, Superstar, Trinoids, Whisper, Wobble, Zarvox. Для ребёнка
7 лет это не «забавно», а пугающе. Движок отбрасывает их по имени
(`UNFRIENDLY_VOICE_MARKERS` в `packages/media/src/voices.ts`), и в настройках
родителя они не показываются.

## Что уже сделано в коде

- `createTtsEngine` — выбор голоса, темп (0.85 для новых слов, 0.7 для «медленно»),
  очередь без запикания, `unlock()` после первого жеста, `voiceschanged`.
- `pickVoice` — точное совпадение акцента → любой английский → `null`.
- Тесты на поддельном синтезаторе: до жеста молчим, смена акцента, отмена очереди,
  отсутствие поддержки `speechSynthesis` (`packages/media/src/media.test.ts`).
- Если голосов нет или синтез заблокирован — движок возвращает `false`, приложение
  остаётся полностью рабочим: весь текст виден, карточки и прогресс на месте.

## Fallback, если голосов нет вовсе

1. Говорим с атрибутом `lang="en-US"`/`"en-GB"` и без явного голоса — системный
   движок сам выберет, что есть.
2. Голосов нет совсем (Chrome Linux, Firefox RFP, iOS без английского пакета) — тишина:
   кнопки звука прячем, упражнения идут с картинками и подписями. Прогресс не теряется.
3. Продолжение трека — запись слов носителем (слот `AudioSource = file` уже есть
   в контракте, task.md §8.4); см. открытый вопрос 13.
